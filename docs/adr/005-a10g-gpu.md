# ADR-005: A10G (g5.xlarge) over L4 and L40S

**Status:** accepted
**Date:** 2026-07-26

## Context

Decode on an 8B model is memory-bandwidth-bound, not compute-bound: it reads
the entire weight set once per token. Bandwidth, not FLOPs, decides the card.

## Decision

`g5.xlarge`: one A10G, 24GB, 600 GB/s, spot-first through Karpenter with
on-demand fallback.

## Alternatives rejected

**L4 (`g6.xlarge`).** 20% cheaper for half the memory bandwidth. Roughly 50%
slower decode to save 20% of the sticker price is a bad trade on a
latency-sensitive path.

**L40S (`g6e.xlarge`).** The right card for a 14B model or an FP8 path, at
1.85x the price. That is the Tier C conversation, not the Tier B one.

**A100 40GB.** Overkill for an 8B; the bandwidth is wasted on a model this
size.

## Consequence

Locked to `sm_86`, so there is no FP8 path without a card change. The KV
cache arithmetic in `docs/inference.md` is specific to this card and must be
redone if it changes.

## Revisit when

Tier C, or a model larger than 8B.
